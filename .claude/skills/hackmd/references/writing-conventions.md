# HackMD 筆記書寫規範

> **原始出處：** https://hackmd.io/@sysprog/linux2026-warmup
> **擷取日期：** 2026-02-27
> **用途：** 課程 HackMD 筆記的書寫規範，所有發布至 HackMD 的內容必須遵守

## 總則

共筆書寫請考慮到日後協作，避免過多的個人色彩，用詞儘量中性。

## 禁止事項

1. **不加 `[TOC]`** — 筆記左上方已有 Table of Contents 功能，不需要畫蛇添足
2. **不變更預設 CSS、不加入佈景主題** — 這是「開發紀錄」，主要用於評分和接受同儕檢閱，不是彰顯「個人風格」的地方
3. **不濫用提示區塊** — 不濫用 `:::info`、`:::success`、`:::warning` 等標示，儘量用清晰的文字書寫。`:::danger` 僅限授課教師作為批注使用，學生不得使用
4. **不使用不必要的 emoji** — 避免使用不必要的 emoji 字元
5. **不張貼完整程式碼** — HackMD 不是讓你張貼完整程式碼的地方，GitHub 才是！只列出關鍵程式碼（善用 `diff` 標示），可附上對應 GitHub commit 的超連結。列出程式碼是為了「檢討」和「便於他人參與討論」，不是用來「假裝自己有付出」
   - 單頁 HackMD 筆記有內容長度限制，記錄洞見和關鍵程式碼，完整程式碼應在 GitHub 儲存庫或 [gist](https://gist.github.com/) 出現
6. **不得由 AI 產生整篇報告直接張貼** — 應依據子主題書寫，斟酌運用 AI 工具潤飾書寫內容，這些都該在 HackMD 的變更紀錄中可見

## 程式碼區塊

貼入程式碼時，避免非必要的行號：手動將 `c=` 或 `cpp=` 變更為 `c` 或 `cpp`。行號只在後續討論明確需要行號時才出現，否則維持精簡的展現。

正確：
~~~
```c
int x = 42;
```
~~~

避免：
~~~
```c=
int x = 42;
```
~~~

## 標點符號

- 中文敘述中使用**全形標點符號**，例如該用「，」而非 ","
- 注意書名號的使用，即 `〈` 和 `〉`，非「小於」和「大於」符號

## 中英文混用

- 避免過多的中英文混用
- 已有明確翻譯詞彙者（如「鏈結串列」、「佇列」），使用該中文詞彙
- 英文留給：變數名稱、人名、缺乏通用翻譯詞彙的場景
- 術語翻譯請依照〈[資訊科技詞彙翻譯](https://hackmd.io/@sysprog/it-vocabulary)〉

## AI 使用揭露

- 可使用 AI 工具，但需要**明確標示**並**指出裡頭謬誤和不精確之處**
- 善用 AI 成果，但人類的書寫不該比 AI 差
- 本課程不接受沒有完整編修紀錄的筆記，學員應當漸進更新並回應授課教師和學員的指教

## 數學公式

- 數學公式**一律使用 LaTeX**，不得用純文字或程式碼格式替代
- 行內公式用 `$...$`，獨立公式用 `$$...$$`
- C 語言運算子出現在 LaTeX 公式中時，須正確跳脫：`\%`（取餘數）、`\&`（位元 AND）。未跳脫的 `%` 在 LaTeX 中是註解符號（後面整行被吞），`&` 是表格對齊符號，都會導致公式算繪錯誤
- 建議使用 `\mathbin{\&}` 讓位元 AND 具備正確的運算子間距

## 原始碼引用

- 引用 Linux 核心原始碼時，**附上 GitHub 連結並指定版本標籤**，讓讀者能直接驗證正確性
- 格式：`https://github.com/torvalds/linux/blob/v{版本}/{檔案路徑}`，可加 `#L{行號}` 定位
- 範例：[`kernel/fork.c#L2293`](https://github.com/torvalds/linux/blob/v6.19/kernel/fork.c#L2293)
- 引用的程式碼片段應忠實呈現原始碼，不得將不同位置的程式碼合併偽裝成單一區塊；若為簡化摘錄，須明確標示省略了什麼

## 寫作風格

本規範明確要求「避免過多的個人色彩，用詞儘量中性」。因此：

- **禁用個人寫作風格模仿** — 撰寫 HackMD 內容時，不得參考或模仿 `notes/writing_style.md` 中記錄的個人書寫語氣
- 用詞應中性、客觀、專業
- 以清晰傳達技術內容為目標，而非展現個人風格
